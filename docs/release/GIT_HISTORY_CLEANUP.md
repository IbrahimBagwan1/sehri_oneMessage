## Step 1 — rotation is what makes the leak harmless (do this regardless)

A key that has been deleted in Google Cloud is useless to whoever has it,
whatever git contains. Rewriting history without rotating protects nothing:
the keys are already in clones, forks, CI caches and chat logs.

1. Google Cloud Console → APIs & Services → Credentials → **delete** both
   keys (`…8go`, `…phw`). Create new restricted keys (LAUNCH_CHECKLIST §2).
2. Confirm each old key is dead. From any terminal, with the full old key:

   ```bash
   curl -s "https://maps.googleapis.com/maps/api/geocode/json?address=Bangalore&key=PASTE_OLD_KEY_HERE"
   ```

   Expected: `"status" : "REQUEST_DENIED"` **and** an error message saying
   the key is **invalid** ("The provided API key is invalid") or expired.
   Any other answer means the key still exists: `"OK"`, or a denial that
   says the app/IP "is not authorized" or the API "is not activated" (those
   come from a live key's restrictions, not from deletion). Deleting can take
   a few minutes to apply.
3. Rotate the non-git secrets listed above the same day (LAUNCH_CHECKLIST §1).

After step 1 the history contains only dead strings. **Stop here unless** the
repository will become public, be shared with people who shouldn't see even
dead keys, or a policy requires a clean history.

## Step 2 — optional: rewrite history with git filter-repo

### What it costs you

- **Every commit hash changes** on every branch that contains the old files
  (all of them). Links to commits in issues, chats or docs will break.
- **Everyone must re-clone.** Pulling into an old clone merges the old history
  back in, re-introducing the keys. Anyone with a clone must delete it.
- **Open pull requests break.** GitHub keeps `refs/pull/*` read-only; those,
  and any **forks**, keep the old commits and cannot be rewritten by you.
- GitHub may keep **cached views** of old commits reachable by hash until its
  garbage collection runs; GitHub Support can purge them on request.
- Branches that exist only on someone's laptop are not rewritten.

The repository today: remote `https://github.com/IbrahimBagwan1/sehri_oneMessage`,
branches `main`, `frontend`, `feature/tracking`, `feature/chat`,
`feature/otp-module`, `feature/poll-system` on the remote, plus local
`release/qa-pass-2`. **Merge or push `release/qa-pass-2` first** (or it will
be left behind on the old history), and ask anyone else with a clone to push
their work and then stop.

### The steps

Run these outside the working folder, in a new empty directory.

1. **Install** git-filter-repo (needs Python 3):

   ```bash
   pip install git-filter-repo
   ```

2. **Back up** the whole repository as it is today — keep this until you are
   sure the rewrite is good:

   ```bash
   git clone --mirror https://github.com/IbrahimBagwan1/sehri_oneMessage.git sehri-backup.git
   ```

3. **Make a working mirror** to rewrite (a separate copy of the backup):

   ```bash
   git clone --mirror https://github.com/IbrahimBagwan1/sehri_oneMessage.git sehri-rewrite.git
   ```

4. **Write the replacements file** `replacements.txt` next to it — one line
   per key, the full old key on the left (copy it from the old `app.json` in
   the backup; do not put this file anywhere it will be committed or synced):

   ```
   PASTE_FULL_OLD_KEY_1==>REDACTED_GOOGLE_MAPS_KEY
   PASTE_FULL_OLD_KEY_2==>REDACTED_GOOGLE_MAPS_KEY
   ```

5. **Rewrite**: replace the keys everywhere, and drop the old generated
   `frontend/android/` folder from history entirely (it is regenerated by
   `expo prebuild` now, so nothing of value is lost):

   ```bash
   cd sehri-rewrite.git
   git filter-repo --replace-text ../replacements.txt --path frontend/android --invert-paths
   ```

6. **Verify** before pushing — both commands must print nothing:

   ```bash
   git log --all --oneline -S "PASTE_FIRST_10_CHARS_OF_KEY_1"
   git log --all --oneline -S "PASTE_FIRST_10_CHARS_OF_KEY_2"
   ```

   Also check the branches look right: `git log --oneline -5 main`.

7. **Push** the rewritten branches and tags (not `--mirror`: GitHub refuses
   updates to its read-only `refs/pull/*`, which makes a mirror push fail):

   ```bash
   git remote add origin https://github.com/IbrahimBagwan1/sehri_oneMessage.git
   git push --force --all origin
   git push --force --tags origin
   ```

   (`filter-repo` removes the `origin` remote on purpose, hence re-adding it.)

8. **Replace your working copy**: rename `E:\onemessage\sehri_oneMessage` to
   keep it as a fallback, clone fresh, and copy over only the untracked files
   you need (`backend/.env`, `frontend/.env`). Do not copy the old `.git`
   folder. Delete the old folder once the new clone builds.

9. **GitHub clean-up**: close and re-open any open pull requests from the new
   branches. If the repository has forks you don't control, or you need old
   commit pages gone now, contact GitHub Support and ask them to remove cached
   views and run garbage collection for the repository.

10. Keep `sehri-backup.git` somewhere private for a few weeks, then delete it
    (it still contains the old keys).

### If something goes wrong

Before step 7 nothing has changed on GitHub — delete `sehri-rewrite.git` and
start again. After step 7, restore from the backup with
`cd sehri-backup.git && git push --force --all origin && git push --force --tags origin`.
